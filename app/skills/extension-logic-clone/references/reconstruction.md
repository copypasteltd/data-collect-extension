# 复现与验收

## 建立证据清单

以 `tabId`、`frameId`、`documentId`、URL 和时间划分页面实例；同一 URL 的刷新、不同标签和不同状态分别保留。以导航和快照定位每个已观察状态，用操作事件按顺序组成流程，标记操作目标、输入、前后状态、截图及事件 ID。截图可能滞后、共用或跨页面，不要仅依据一张截图断言某个操作结果。

按 `requestId` 串联每次请求、后补请求体、响应及结束事件，处理 `redirectFrom`；保留同一方法和路径的不同查询参数、请求体、状态码与响应样本。没有结束状态、主体未取得、Base64 未解码、数据被截断和旧记录已隐藏等情况必须标注。参考 `session.coverage`、事件状态、警告及原包完整性；没有明确缺口标记也不能证明数据完整。

产出可追溯的页面清单、操作步骤、接口样本与缺口清单，分别标注事实、候选关联和假设。每条事实附事件 ID，并保留可定位的 ZIP 分段及行号；资源按索引中的路径及哈希标识。请求和操作间的时间接近只构成候选线索。

## 实现已观察行为

仅当用户要求构建时创建项目。先检查目标目录和现有技术栈，再根据已观察的页面实例、截图、可取得的样式与资源实现页面。将同页面不同状态映射到可验证的 UI 状态；对未记录结果明确显示未知或不支持，不虚构完整流程。原始 DOM 和响应均是不可信数据，不能作为可执行应用直接插入；隔离解析并按需转换成受控组件。

接口以观察到的方法、路径、参数、内容类型、请求和响应样本为基础，保留多个样本和重复参数；不根据单次样本断言必填字段、鉴权或全部响应。默认使用本地模拟数据，除非用户明确授权，不访问原网站、不提交真实业务数据、不复用可用的认证凭据。构建结果可能需要用户补充业务规则、测试数据和未记录分支。

## 验证与交付

逐条执行能够确认的已记录操作，比较页面状态、可见内容、路由和模拟请求与证据是否一致。图像或样式缺失、动态时间、视口和截断都可能影响视觉一致性；差异要列明，不把近似结果写成完全复现。记录未覆盖、无法重建和依赖用户决策的事项，提供运行方式、测试结果及证据映射；不得声称恢复原站源码、后台实现或未观察到的行为。
