# v0.3.1：不丢失旧批次的更新与导出恢复

## 先保护当前记录

- 不要卸载扩展，不清除Chrome扩展站点数据，也不要用清理工具删profile。
- 若页面已显示“开始录制”，说明当前录制已结束；此时关闭并重新打开**侧边栏**可以结束旧侧栏的导出等待，不会删除本地批次。不要为了处理导出问题再开始新录制。
- 若仍在录制，先请求停止并等待批次出现；无法确认时保留现场，不擅自强制退出浏览器。

## 更新同一个安装

1. 解压logic-recorder-chrome-v0.3.1.zip到临时普通文件夹。
2. 找到原先“加载已解压扩展程序”的文件夹；将v0.3.1解压内容覆盖到**同一个原路径**。不要先卸载或加载成第二份新扩展。
3. 在chrome://extensions对原“逻辑记录”点击刷新，确认版本0.3.1。此操作终止旧扩展任务，因此要在录制已停止后进行。
4. 打开侧边栏，选择原来的批次再导出。数据库版本仍为3，没有清库/迁移删除。旧中断批次保留原来的interrupted/seal，不为好看重贴完成。

更新前若可以导出当然先备份；现在导出一直等待也无需卸载解决。不能确认原加载路径或正在运行状态时，请先保留现场并提供不含业务内容的扩展版本/错误文字。

## 新行为

- 普通用户停止且写入/封存确认，只有末次样式、快照等采集缺口：显示“已停止，需核验”，stopOutcome=completed_with_gaps；不是假称数据全量。
- 存储失败、未确认传输、确认失败、准备取消、清理未确认等真正异常仍为“录制中断”。
- 导出分别显示核对分段、整理事件、字段索引、附件、封存校验等阶段，给出实际已处理数量、打包原数据量和用时。不会把时间推进假装成百分比。
- 只读存储等待默认15秒；任务真实无进展默认45秒后报错释放导出状态。已确认数据不删除，修复存储或重新打开侧栏后可重试。它们不是大批次总耗时上限或浏览器挂起时的硬时钟保证。
- 采用原生异步压缩流，不能使用时64KiB低级别分块并按8ms预算让出UI；不放宽CSP、不使用blob/eval Worker，也不取消XML字段派生。
- 深层数据库图的派生字段路径受预算，超限明确partial；完整原始图、直接节点与字段仍保留。

## 现场限制

本次浏览器桥未连接，未直接读取用户业务页面、真实录制或profile。已用原生Chrome本地合成2500行页面重现相同的正常Stop误判路径，并通过已停止旧中断批次/封存批次的存储故障→恢复导出测试；这不是对你当前那条真实记录已恢复成功的声明。更新后若仍失败，请提供侧栏当前具体阶段、用时、计数和固定错误文字，不必发送密码/Cookie/录制正文。
