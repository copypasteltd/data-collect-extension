# v0.5.0：限额可设置，默认20倍

## 更新

先停止录制，备份原扩展程序目录，再用logic-recorder-chrome-v0.5.0.zip覆盖原加载目录；在chrome://extensions刷新原扩展并确认版本0.5.0。不要卸载、清浏览器数据、改原路径或加载第二份。原目录名字带旧版本号也可保留。文件覆盖与Chrome运行时切换是两回事。

本版仍使用flow-v1库，已有批次不重写；旧批次缺settings按原1倍解释，不套当前默认20倍。旧重型logic-recorder库不读取、不迁移、不删除。

## 页面设置

侧栏展开“录制限额设置”，分别设置容量倍率、待处理队列倍率、页面采样倍率。均为1–20的整数，默认20；页面会显示换算后的真实上限。修改后点击“保存到本机”，可点“恢复默认20倍”。空值、小数、负数及21以上不会保存；未保存草稿不能开始新批次，停止按钮仍可用。

设置保存在当前Chrome配置的扩展本地存储，关闭重开仍保留。正在录制时也可保存，但只对下一批生效；当前批次固定使用开始时的设置。开始前仍需切到获准业务页面；页面范围/权限规则没有扩大。

## 默认20倍限额

| 项目 | 默认及最大 |
| --- | ---: |
| 单批保存总量 | 1280MiB = 1.25GiB（约1.2GB） |
| 提醒线 | 960MiB |
| 普通采集/收尾预留 | 1260MiB / 20MiB |
| 单个接口正文 | 40MiB |
| 正文/DOM/资源/截图/元数据集合 | 480 / 320 / 160 / 240 / 80MiB |
| 后台待处理 | 1280项 / 160MiB |
| 页面待处理 | 640项 / 120MiB |
| 待处理网络任务 | 2560项 |

子预算独立且受总预算约束，不保证每批都接近总额才停止；达到内容/队列限额仍受控停止，实际存储/通信错误仍报告。倍率不增加空闲/录制时长计时，不放宽权限、标识协议、递归深度或时间等待；根流程范围保持根页＋必要框架＋一个可信归因子页。

这是保存内容与事件的策略上限，不是ZIP大小、Chrome内存或可用磁盘保证。配置20倍不代表对任意网站或整1.25GiB负载都已验收。

## 导出与读取

导出按页读取、逐块核验并写Chrome私有临时文件，下载完成/失败后删除本次临时输出，不删除录制。新导出使用流式STORE，ZIP压缩率可能低于旧版；不再在内存中组装整个大包。不支持磁盘导出的环境仅允许128MiB内存回退，超限明确报错。v3格式保持兼容；代码保留ZIP64边界支持。

配套读取skill版本0.5.0可解释每批settings/limits/runtimeLimits及旧1倍快照，严格核预算、账本、引用和封存。其提取默认上限同步到1280MiB、ZIP/展开1400MiB，按块复制原字节，不自动执行内容或访问原站。使用已安装skill可直接：

```text
$extension-logic-clone 读取 <recording.zip>，先检查范围、设置和缺口，再整理业务证据。
```

本正式发布包含Chrome扩展0.5.0和配套读取skill0.5.0；旧v0.4.0发布保持不变。已采原值可能含认证头、密码和业务资料，ZIP/SQLite未加密，需保护文件与分享。
