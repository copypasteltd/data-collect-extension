# Chrome 扩展需求梳理

版本：2.1<br>
日期：2026-11-09<br>
状态：需求草案

## 1. 项目目标

开发一个 Chrome 扩展。用户点击扩展图标后，在浏览器侧边栏中开始和停止录制。录制期间，扩展尽可能全面地记录用户实际访问的页面、实际发生的浏览器行为和页面交互、页面状态变化、相关接口请求、Cookie 及其他信息，并将操作与页面截图关联。

录制结束后，系统归档录制内容，供用户下载 ZIP 记录包。其他人取得记录包后，应能够理解和复现录制者实际看到的页面和操作过程，并利用记录信息快速重建所经过的页面、已触发的模块逻辑和相关请求规范。

本文件整理目标需求；尚未确定的产品选择列于末尾，不视为已决定的实现限制。

**范围边界**：只要求覆盖录制时用户实际走过的页面和触发的流程；未访问页面、未触发条件分支和无法从浏览器观察的服务端内部实现，不作为录制完整性的既定要求。同一页面不同状态和同一接口不同响应，只有实际出现过的才构成该次录制的目标范围。

**界面约束**：录制、记录管理、导入、查看、回放、页面和接口资料等所有用户界面，均在 Chrome 扩展侧边栏的子页面内实现，不打开独立网页、浏览器标签页或本地程序页面。

## 2. 用户角色

- **录制者**：安装扩展、启动和停止录制、操作目标站点、下载记录包。
- **接收者**：取得记录包，查看和复现录制内容，分析并重建目标站点。
- **项目管理者**：确定录制范围、数据使用权限和交付方式。

## 3. 端到端流程

1. 用户安装并打开扩展，浏览器展示侧边栏。
2. 用户点击“开始录制”，系统创建一次录制任务并显示录制状态。
3. 用户正常使用浏览器和目标站点；系统持续采集操作、页面、截图、网络和状态变化。
4. 用户点击“停止录制”，系统停止采集，对录制内容整理、关联和归档。
5. 用户在侧边栏查看录制结果，点击“下载记录包”，获得 ZIP 文件。
6. 接收者在其他环境打开或解析该记录包，查看页面与操作过程，利用其中的数据进行站点复现和重建。

## 4. 功能需求

### 4.1 侧边栏与录制控制

| 编号 | 功能 | 需求 |
| --- | --- | --- |
| R01 | 打开侧边栏 | 点击扩展图标后展示侧边页面。 |
| R02 | 开始录制 | 用户点击开始后，建立录制任务并记录开始时间、浏览器环境与初始页面状态。 |
| R03 | 录制状态 | 录制中明确显示状态、持续时间及当前记录概况。 |
| R04 | 停止录制 | 用户点击停止后结束录制，并进入整理和归档流程。 |
| R05 | 归档状态 | 展示归档中、完成或失败状态，以及必要的错误信息。 |
| R06 | 录制记录 | 展示已完成的录制任务，支持识别、查看和下载。 |
| R07 | 下载记录包 | 将一份录制内容打包为 ZIP，供用户下载。 |

### 4.2 浏览器行为记录

录制期间记录用户与浏览器相关的行为及其先后顺序，包括：

- 标签页和窗口的打开、关闭、切换，以及与目标页面相关的变化。
- 页面访问、刷新、跳转、重定向、前进、后退、地址变化及单页应用路由变化。
- 鼠标点击、双击、右键、移动、悬停、拖拽和滚动。
- 键盘输入、按键、组合键、粘贴、焦点变化及输入法相关操作。
- 输入、修改、选择、勾选、上传、提交等表单交互。
- 弹窗、菜单、展开收起、选项卡切换以及其他可识别的页面交互。
- 每项操作的时间、所属窗口和标签页、页面与框架、操作对象、元素信息、坐标及相关上下文。

### 4.3 页面与状态记录

记录用户访问到的页面及其变化，供之后理解和还原：

- 页面地址、标题、加载过程、页面层级、视口、滚动位置和展示环境。
- 页面结构、文本、布局、样式、图片、字体及其他可用于还原页面的资源信息。
- 页面初始化状态、操作前后状态、动态元素、表单内容和结构变化。
- 页面内嵌框架、组件、弹窗、悬浮层、Canvas、视频等呈现内容及其相关状态。
- 用户操作、页面变化和后续网络请求之间的关联信息。

### 4.4 操作截图

- 针对页面中的点击及其他用户操作进行截图，记录用户操作时及操作后的页面表现。
- 截图与操作事件、页面、标签页、时间及页面状态建立对应关系。
- 保存截图所需的视口、缩放比例、滚动位置及其他上下文信息。
- 记录截图结果，便于接收者按时间和操作步骤查看。

### 4.5 网络请求与接口信息

记录与页面及操作相关的接口和资源请求，形成可供分析与重建的请求资料：

- 请求地址、方法、参数、请求头、请求体、发起时间、来源页面及触发操作。
- 响应状态、响应头、响应体、返回时间、耗时、错误和重定向。
- 页面资源请求、异步接口、上传下载及实时通信相关数据。
- 相同接口在不同参数、页面状态及操作下的请求和返回样本。
- 记录请求与页面、操作、业务流程和返回结果之间的关系。

### 4.6 Cookie 与其他状态

- 记录与用户访问及站点运行相关的 Cookie、属性及其变化。
- 记录页面本地存储、会话存储、数据库、缓存等与页面状态有关的信息及变化。
- 关联状态变化发生的时间、页面和对应操作，以辅助理解用户当时的会话状态。

### 4.7 时间线与关联

- 为一次录制生成统一时间线，整理浏览器行为、页面、截图、网络请求和状态变化。
- 对每项信息标注时间、所属录制任务、页面及相互关系。
- 支持从某次操作追踪其前后截图、页面变化和相关请求，也支持从页面或请求反查相关操作。

### 4.8 归档与 ZIP 记录包

每次录制形成一份独立记录包，包含：

- 录制任务基本信息、开始和结束时间、浏览器及页面环境。
- 浏览器行为和页面操作时间线。
- 页面内容、结构、状态变化与相关资源。
- 操作截图及截图与事件之间的关联。
- 请求、响应、Cookie 和其他站点状态信息。
- 页面、操作、请求和状态之间的索引及关联信息。
- 供接收者读取的格式说明、清单和必要的完整性信息。

记录包应便于保存、传递、解析和复用，并能识别其格式版本与内容范围。

### 4.9 复现与站点重建

接收者应能根据记录包：

1. 了解录制时的浏览器环境、访问路径及完整操作顺序。
2. 按页面和时间查看录制者看到的内容、操作截图及状态变化。
3. 复现页面展示及用户在录制过程中执行的交互。
4. 查找每一步相关的请求、响应、Cookie 和其他状态变化。
5. 梳理站点的页面结构、模块组成、操作流程和页面之间的关系。
6. 梳理接口地址、请求方式、参数、响应结构以及页面与接口的对应关系。
7. 利用记录内容快速重建用户实际经过的页面、触发过的模块逻辑及相关请求规范。

记录包的读取、查看、回放和重建所需工具及其交付形态有待进一步明确。

## 5. 数据管理与使用要求

- 录制、归档、下载和后续使用应有清晰的用户操作入口和状态提示。
- 需要考虑录制数据中可能出现的个人信息、业务数据、登录状态和其他敏感内容，明确授权、存储、分享和使用规则。
- 录制时间较长或数据量较大时，系统应能提示录制、存储、归档和下载的状态。
- 发生录制中断、数据缺失、归档失败或下载失败时，应提供可理解的提示与结果说明。

## 6. 核心验收方向

1. 用户可以从扩展图标打开侧边栏，并开始、停止一次录制。
2. 完成站点操作后，可下载对应的 ZIP 记录包。
3. 记录包包含本次访问的页面、操作、截图、请求、Cookie 和其他相关状态信息，并具有可追溯的关联。
4. 接收者可依据记录包按顺序查看和复现录制过程，理解页面及交互。
5. 接收者可利用记录内容梳理并重建实际经过的页面、已触发的模块逻辑和相关接口请求规范。
6. 录制或归档过程中发生的异常能够被识别和说明。

以上是目标验收方向；具体覆盖范围、质量指标和判定标准需要在产品方案与技术验证后确定。

## 7. 待确认事项

1. 录制范围是当前标签页、某一站点、一个窗口，还是浏览器中的所有窗口与标签页？跨域登录和新标签如何处理？
2. 是否需要暂停和恢复录制、管理历史记录及删除记录？
3. 截图是每次操作前后均需要，还是可以根据操作类型配置？是否要求整页截图或视频？
4. 接收者需要的是逐步查看、可交互回放、自动执行真实操作，还是以上全部？
5. 接收者通过扩展侧边栏子页面导入和查看 ZIP；重建资料的具体输出形式还需确定。
6. 已确认记录包保留浏览器实际提供的原值；加密及分级分发是否需要作为后续能力？
7. 目标站点类型、预期录制时长、数据规模、Chrome 版本以及扩展的发布和使用环境是什么？
8. 所说的“重建”要求生成页面和接口文档，还是要求交付可运行的前后端系统？

## 8. 统一业务对象与关联

为保证各模块记录能互相查找，一次录制应组织为以下对象：

| 对象 | 含义 | 核心关联 |
| --- | --- | --- |
| 录制任务 | 从用户开始到停止的一次记录 | 包含录制片段、页面、事件、请求、资源和归档 |
| 录制片段 | 连续采集的时间区间 | 属于录制任务；暂停或异常中断形成边界 |
| 页面实例 | 某标签页中一次具体页面加载或导航产生的实例 | 关联窗口、标签、地址、页面状态和事件；同地址可有多个实例 |
| 页面状态 | 页面在某一时间的内容和交互状态 | 属于页面实例；可关联快照、截图及状态变化 |
| 操作事件 | 用户或浏览器发生的一次可观察行为 | 关联时间、页面、目标元素及相关状态 |
| 网络请求 | 一次独立的请求与响应过程 | 关联页面、帧、时间、请求/响应、可能的触发事件 |
| 状态变化 | 页面、Cookie 或其他存储的变化 | 关联变化前后值或摘要、时间和来源 |
| 截图与资源 | 页面截图、图片、样式、字体等内容 | 通过标识关联到页面、状态、事件或请求 |
| 业务流程 | 由连续操作、页面状态和请求组成的实际经过路径 | 可人工命名或从时间线整理，包含来源证据 |
| 归档包 | 某个录制任务的可交付文件 | 包含版本、清单、索引、数据和完整性报告 |

各对象拥有唯一标识；记录发生时间和关联依据。时间相近并不必然代表某次操作触发某个请求，无法确定时应标记为可能关联，避免把推测当作事实。

## 9. 模块一：侧边栏与任务控制

### 9.1 页面组成

侧边栏提供当前任务状态、开始/停止入口、录制时长、当前页面信息、已采集数量、异常提示和归档进度；提供历史记录列表及记录包下载入口。需要用户决定的录制范围、敏感信息和截图规则应在开始前展示。

### 9.2 操作规则

1. 用户选择录制配置并开始后，系统创建任务，检查所需权限和采集准备情况。
2. 采集就绪后显示录制中；准备失败时显示原因，不把任务显示为正在正常录制。
3. 录制中显示所属范围，页面跳转或标签变化时保持状态可辨识。
4. 用户停止后不再接收新的用户操作；对已接收事件和在途数据进行有界收尾，再生成归档。
5. 归档完成后展示结果和下载入口；失败时展示原因及可恢复、可导出的部分。

任务建议状态：`未开始 → 准备中 → 录制中 → 停止中 → 归档中 → 已完成`，另有 `暂停中`、`异常中断` 和 `失败` 状态。暂停、侧边栏关闭后的行为以及同时运行多少任务，待产品确认。

### 9.3 验收

- 用户可识别任务是否正在录制、正在归档或已完成，不会将准备失败误认为成功。
- 录制完成后能找到对应任务并下载；异常时能看到明确结果。

## 10. 模块二：范围、权限和用户授权

### 10.1 录制范围

一次任务需明确记录受监测的窗口、标签、站点或域名范围，以及是否包含新标签、跨域跳转和第三方嵌入页面。开始前已经发生的请求和操作不属于事后可采集的历史；系统应记录启动时已经呈现的页面状态，并让用户决定是否从页面初始加载开始重新操作。

### 10.2 权限与披露

- 开始采集前向用户说明采集类别、范围、使用目的、保存位置和导出可能包含的敏感内容，获得明确同意。
- 按功能和站点申请必要权限；被拒绝时说明受影响模块，展示是否允许继续以及由此产生的缺口。
- 无痕窗口、浏览器内部页面、系统对话框和未授权站点等，应按实际授权及可用能力处理并明确状态。
- 用户应能识别录制中状态，并在需要时停止。

### 10.3 验收

配置的范围与实际采集范围可核对；未经授权或超出范围的页面不会被当作已完整采集的页面；权限拒绝及范围变化均有明确提示。

## 11. 模块三：浏览器、页面与导航

### 11.1 采集内容

- 窗口及标签的创建、关闭、切换和前后关系；新标签由哪个操作打开。
- 页面 URL、标题、加载开始和完成、跳转与重定向、刷新、前进后退、路由及锚点变化。
- 页面加载失败、关闭、重新加载、离开和回到页面。
- 视口尺寸、设备像素比、缩放、滚动位置、页面可见性和录制环境。

### 11.2 处理规则

同一个 URL 的多次访问分别建立页面实例；同一实例内的弹窗、筛选结果、选项卡和表单变化建立页面状态，不应只按 URL 合并。跨域跳转、新窗口和嵌入框架维持可追踪关系；无法识别时保留未知标记。

### 11.3 验收

给定一次包含跳转、刷新、浏览器返回和新标签的操作，接收者可以按时间线还原页面访问顺序，并区分同一地址的不同访问实例。

## 12. 模块四：用户操作采集

### 12.1 操作分类

| 类别 | 示例 | 应记录的上下文 |
| --- | --- | --- |
| 指针 | 点击、双击、右键、悬停、拖放 | 元素、坐标、按钮、起止位置、页面状态 |
| 键盘与输入 | 键入、删除、粘贴、组合键、输入法 | 元素、输入前后状态、时间、内容处理规则 |
| 表单 | 输入、选择、勾选、提交、文件选择 | 字段标识、状态变化、提交动作及处理结果 |
| 页面操作 | 滚动、缩放、焦点变化 | 容器、前后位置、视口及时间 |
| 浏览器操作 | 页面跳转、标签切换、关闭 | 窗口、标签、页面与时间 |

### 12.2 元素与事件信息

记录操作发生时间、事件类型、页面/框架、元素标签、可访问名称与角色、可用定位信息、元素位置和尺寸、操作前后原始状态及采集结果。对高频事件可配置采样或合并，保留合并规则与时间区间。

### 12.3 验收

在测试页面执行点击、键盘输入、表单提交、滚动和拖拽后，时间线能列出已接收的相应事件，展示目标元素及上下文；合并和无法获取的内容具有状态说明。

## 13. 模块五：页面内容、状态与资源

### 13.1 页面初始内容

为进入录制范围的页面建立初始状态，记录可获取的页面结构、文本、样式、布局、可视区域、表单及资源引用；区分录制开始时已经加载的页面与录制中发生的首次加载。

### 13.2 页面状态变化

记录 DOM 结构和文本变化、元素显示隐藏、样式变化、表单值变化、弹窗开关、列表和分页结果、加载状态、滚动位置及相关时间。状态变化应可关联之前的页面状态、可能的操作及请求响应。

为避免只有孤立增量而无法复原，应建立初始快照及适当的检查点，并维护检查点后的变化序列。嵌入框架、Shadow DOM、Canvas、视频和其他复杂呈现内容分别记录实际采集结果。

### 13.3 静态资源

记录页面实际使用且可取得的图片、样式、字体、脚本及其他资源的地址、类型、大小、内容或引用、加载结果和所属页面。相同内容可去重，但保留所有引用关系。资源不可取得、被排除或截断时记录原因。

### 13.4 验收

对测试流程中的初始页面、弹窗打开、筛选结果和提交后状态，接收者能分别定位到对应快照或变化及截图；无法取得的资源有明确标记。

## 14. 模块六：截图采集与事件关联

### 14.1 触发和内容

关键操作应发起截图请求；记录操作前最近可用画面、操作后的画面及各自与操作的时间差。截图关联任务、页面实例、事件、窗口、标签、视口和滚动位置。截图范围及操作类别应可配置。

### 14.2 排队和结果

对连续操作的截图请求进行排队和处理；每个关键操作保留处理结果：成功、与其他操作共用、跳过、失败或无法取得，并记录原因。系统不应通过悄然切换用户标签页取得截图。对异步加载后的画面，记录实际捕获时间，不能把后续截图表述为操作瞬间画面。

### 14.3 验收

在连续操作和页面跳转测试中，每个关键操作均能查到截图或明确的未取得原因；截图不会被错误标记为其他标签页或页面的画面。

## 15. 模块七：网络请求与响应

### 15.1 记录字段

- 基本信息：请求标识、页面/框架、来源、资源类型、URL、方法、时间、发起上下文及可能的操作关联。
- 请求内容：查询参数、请求头、请求体、内容类型和大小；保留浏览器提供的原值，并明确标注二进制、上传数据及超限内容的实际采集状态。
- 响应内容：状态码、响应头、响应体、内容类型、大小、完成时间、耗时和失败原因。
- 生命周期：重定向、缓存、加载失败、中断及可识别的 Service Worker 来源。
- 实时通信：记录可获得的 WebSocket 连接与消息、事件流及其收发时间和所属页面。

### 15.2 采集结果与接口整理

对请求头、请求体、响应头和响应体分别标注采集成功、未授权、被截断、不可获取或失败及原因。保留同一接口多次调用的不同参数和响应样本；整理时按方法和路径归组，同时保留每次请求的原始上下文。

### 15.3 验收

测试流程中触发查询和提交请求后，能定位请求、响应及相关页面/操作；多次调用样本不被覆盖；缺失内容有原因，推断出的关联有标记。

## 16. 模块八：Cookie 和站点状态

### 16.1 记录对象

在已授权范围内，记录与实际访问站点相关的 Cookie 属性和变化，以及可获取的 localStorage、sessionStorage、IndexedDB、缓存等状态或变化。对各存储区记录来源、页面或域、时间、键、值或处理后的摘要、操作类型和采集结果。

### 16.2 状态关联

保存录制开始时可获取的初始状态，以及录制期间可观察的新增、修改、删除；页面、接口、操作与状态变化存在关联时一并索引。无法观察全部变化或取得完整快照时标记缺口。

### 16.3 验收

测试站点修改 Cookie 和本地状态后，可在时间线定位到变化并确认所属站点；实际取得的值原样记录，未记录的部分明确标识。

## 17. 模块九：时间线与业务流程梳理

### 17.1 时间线

按发生时间展示导航、操作、页面变化、截图、网络请求和状态变化；支持按窗口、标签、页面、事件类型、接口和时间筛选。单个事件详情展示前后状态、截图、目标元素和相关请求，并提供来源跳转。

### 17.2 业务流程

支持将实际经历过的连续事件整理为流程，例如“打开客户列表 → 搜索客户 → 打开详情 → 修改资料 → 提交 → 展示结果”。每个步骤关联页面、操作、状态、接口及结果；可记录流程名称、备注和起止位置。自动识别与人工整理的方式及交互待确认。

对流程中观察到的规则记录证据，例如某字段必填、某按钮触发特定请求、提交后出现成功提示；区分页面实际显示、请求实际返回、人员补充说明和系统推测，不推导未发生过的分支。

### 17.3 验收

接收者可以从一个已录制流程找到每个步骤的原始事件、截图和相关接口，并识别推测或缺失信息。

## 18. 模块十：存储、归档和下载

### 18.1 持久化与异常

录制中分批保存已接收数据及任务状态，避免只在结束时一次写入。处理扩展或浏览器意外退出、目标页面关闭、采集器断开、空间不足等情况；重启后能识别未完成任务，提供恢复、终止或导出已有内容的合适入口，并标注中断时间段。

### 18.2 归档流程

停止后完成待写入数据处理，建立索引、清单、统计和缺失报告，打包为 ZIP。归档过程显示进度、体积和结果；超时或失败的内容应明确标记，部分归档不能显示为无缺失完成。

### 18.3 记录包逻辑结构

```text
recording.zip
  manifest.json             # 版本、任务信息、环境、配置、状态
  timeline/                 # 页面导航、操作和状态变化
  pages/                    # 页面索引、快照和变化
  screenshots/              # 图片及其事件关联
  network/                  # 请求、响应和主体数据
  state/                    # Cookie 与其他站点状态
  resources/                # 页面资源及引用
  flows/                    # 已整理业务流程及证据索引
  reports/                  # 采集结果、缺失和处理说明
  integrity.json            # 内容清单及完整性校验信息
```

具体格式和字段在设计阶段确定；每个数据项需能关联来源及采集状态。校验信息用于发现损坏，不自动证明来源可信。

### 18.4 验收

正常停止后的 ZIP 可以重复下载、读取，清单中的文件与索引一致；故障情况下能识别部分结果及缺失区间。

## 19. 模块十一：导入、查看与回放

### 19.1 导入和检查

接收者选择 ZIP 后，查看器检查格式版本、文件清单、完整性、数据规模与缺失报告；对不兼容或损坏的文件给出说明。导入时防范异常路径、异常压缩体积及恶意内容。

### 19.2 查看

提供录制概览、页面清单、截图、时间线、事件详情、请求详情、状态变化、资源及业务流程视图；能从任一视图跳转关联证据。

### 19.3 回放

支持按时间播放用户实际操作轨迹，暂停、继续、调整速度、逐步前进和跳转指定事件；展示相应页面状态、截图、操作目标及请求。页面无法还原或事件缺少证据时明确提示。

回放需区分只读的记录播放、基于已录数据的离线交互模拟，以及对真实站点重新执行操作。后者可能提交或修改真实数据，是否纳入产品及授权方式待确认。未记录的输入、页面和分支不能显示为已经验证可用。

### 19.4 验收

接收者在另一环境导入记录包后，可按时间查看实际记录的流程，定位页面与事件证据，并在缺失处看到清楚说明。查看器默认不应因为打开记录包而向原站点提交业务操作。

## 20. 模块十二：页面、业务与接口重建资料

### 20.1 页面与模块

输出或展示实际经过的页面清单、页面状态、布局与资源索引、模块和组件候选、页面跳转关系，以及关键交互前后的变化。相同页面不同状态需要可区分，并链接原始证据。

### 20.2 业务流程

按实际录制的流程整理入口、前置页面状态、用户操作、页面反馈、关联请求和结果；以观察样本描述已出现的条件和反馈，标明无法从记录判断的服务端规则。

### 20.3 接口规范

按实际观察到的接口整理方法、路径、参数、请求体、响应码、响应字段、调用页面、触发步骤及样本；对字段类型和必填性注明来自实际样本还是推断。可讨论输出机器可读的接口规范草稿，但不能将单次样本当作全部接口契约。

### 20.4 验收

对测试流程生成的页面、流程和接口资料，均能追溯到实际录制事件或样本；未访问页面、未触发的规则和缺失信息显示为未知。

## 21. 模块十三：数据安全与共享

- URL、输入、DOM、截图、请求/响应、Cookie 和站点存储保留实际取得的原值。
- 录制前明确采集和导出范围；记录包可能包含认证凭据、个人信息和业务数据。
- 明确数据保存位置、保留期限、删除方式和是否允许加密；不应默认将录制内容上传到外部。
- 浏览器未提供、权限不足及超出限制的数据应在缺失报告中说明。

## 22. 非功能要求与验收方法

| 方面 | 需求 | 验收方式 |
| --- | --- | --- |
| 覆盖可见性 | 不以“全部成功”掩盖无法采集内容 | 报告分别统计成功、缺失、截断、失败及原因 |
| 顺序和关联 | 尽量保持操作、页面和网络的发生顺序 | 对标准测试流程核对时间线和关联；不确定的因果关系有标记 |
| 性能 | 录制不应使目标流程无法正常使用 | 在代表性设备与目标站点测量延迟、内存和包体，再确定阈值 |
| 容量 | 可应对预期录制时长和资源数量 | 测试长时间录制、资源上限、磁盘不足和归档 |
| 可靠性 | 避免异常退出导致整个任务不可用 | 模拟中断，检查已落盘数据及恢复结果 |
| 可移植性 | 接收者可在其他环境导入和读取 | 在约定的目标系统及浏览器版本验证 |
| 安全性 | 查看与导入不应触发未经授权的业务操作 | 使用受控测试站点检查网络访问、脚本和表单提交 |

性能、时长、体积和覆盖比例暂不设未经验证的固定数值；需选定目标环境后制定测试数据和可量化门槛。

## 23. 代表性验收流程

1. **客户查询与修改**：进入列表、搜索、打开详情、修改字段、提交并返回，核对页面状态、各操作截图及接口关联。
2. **动态页面**：单页路由、弹窗、分页和异步刷新，核对不同状态及变化序列。
3. **多标签和跨域**：打开新标签及进入登录页面，核对范围、权限、导航关联和未覆盖提示。
4. **连续操作**：快速输入、点击和滚动，核对事件顺序、截图处理结果和数据量。
5. **异常恢复**：录制时关闭页面、断开采集或空间不足，核对中断提示、已有数据和部分归档。
6. **跨环境交付**：将 ZIP 移至另一环境导入，检查时间线、截图、接口样本、流程资料和完整性报告。
7. **原值记录**：在虚构测试数据的输入、截图、请求和响应中放置认证类字段，核对原值是否贯穿采集、归档和查看。

## 24. 建议的实施顺序

1. **采集验证**：选择实际目标站点，验证页面、事件、截图、网络、Cookie 和权限覆盖情况。
2. **录制与交付闭环**：完成侧边栏、持久化、停止归档、ZIP 下载、基本缺失报告。
3. **查看与回放**：完成导入、时间线、页面状态、截图及请求关联查看。
4. **重建资料**：完善页面关系、业务流程、接口样本与可追溯的规范草稿。
5. **高级能力**：按目标站点验证复杂图形、实时通信和交互模拟；是否加入真实站点自动重跑另行确定。
