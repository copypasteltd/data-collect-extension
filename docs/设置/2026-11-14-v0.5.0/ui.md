# v0.5.0 录制限额设置 UI

容量、待处理队列、页面采样三项倍率均为 1–20 的整数，默认 20。数值统一从 [flow-config.js](../../../app/src/flow-config.js) 派生。

侧栏保留开始、停止、选择批次与导出四个主要操作，增加默认折叠的“录制限额设置”。三个 number 输入均有可见标签、当前已保存倍率和默认倍率；min=1、max=20、step=1。初始化和读取失败重试使用 GET_LIMIT_SETTINGS，保存使用 SAVE_LIMIT_SETTINGS，恢复默认 20 倍使用 RESET_LIMIT_SETTINGS；设置请求沿用 8 秒超时。

读取成功前字段为空且开始不可用，不以默认值掩盖失败。读取失败显示错误及重新读取入口。修改草稿立即禁用开始，用户先保存，再单独点击开始；不将保存串成自动开始，草稿也不会作为 START 附加设置悄悄应用。独立开始操作仍按当前业务标签查询、页面权限请求、START 的顺序执行；真实 Chrome 权限手势由原生联调确认。

空值、非整数、范围外值在字段旁显示 role=alert 错误，以 aria-invalid、aria-describedby 关联输入；无效草稿不写入后台。保存失败保留草稿并显示错误，不显示成功提示。成功后才更新当前已保存值。状态轮询只更新活动录制和批次列表，不覆盖草稿。

录制期间可以保存或恢复限额，界面明确“仅下一批生效”，当前批次仍用启动快照。设置请求忙碌、读取失败、保存失败和导出等待不占用停止操作。活动容量和提醒使用 GET_STATUS 的 active.budget.limitBytes；缺少设置快照的旧批仍按自己的 limitBytes 显示。

20 倍预览包括：

| 项目 | 限额 |
| --- | --- |
| 单批总量 | 1280 MiB（1.25 GiB） |
| 提醒阈值 | 960 MiB |
| 普通采集 / 收尾预留 | 1260 MiB / 20 MiB |
| 单份接口正文 / 单条记录说明 | 40 MiB / 640 KiB |
| 接口正文 / 页面快照 / 资源合计 | 480 MiB / 320 MiB / 160 MiB |
| 截图 / 记录说明合计 | 240 MiB / 80 MiB |
| 后台待处理 / 请求 | 1280 项、160 MiB / 2560 项 |
| 页面待处理 | 640 项、120 MiB |
| 页面每次提交 / 后台每次提交 | 160 项 / 1280 项、80 MiB |
| 页面快照 / 框架采样 | 240000 个节点 / 640 个框架 |
| 表单 / 资源采样 | 2560 / 2560 项 |
| 样式采样 | 640 份 / 160000 条规则 |
| Shadow 页面采样 | 320 个宿主 / 40000 个节点 |

有效草稿即时派生预览，标为草稿；已保存状态标为当前已保存限额。界面说明这些是采集策略上限，磁盘空间或浏览器限制仍可能产生错误，倍率不会扩大录制页面范围；不将边界测试描述为 1.25 GiB 满负载实测。

样式沿用绿色、紧凑间距和原生 details/summary，没有新增框架。输入、折叠标题、设置按钮和主要操作最小高度为 44px，保留键盘焦点轮廓。字段与预览使用可收缩列、文本换行、可换行按钮组适配 320px 侧栏；实际宽度、键盘行为和像素尺寸由父任务原生验证确认。

导出保留归档结果，等待 downloadBlob 完成或失败后，才在导出函数 finally 中 await cleanup。关闭侧栏只中止归档生产者，不直接清理下载中的文件；下载开始后须等下载函数结束再清理结果。界面不显示归档返回的存储格式或内部 metrics。
