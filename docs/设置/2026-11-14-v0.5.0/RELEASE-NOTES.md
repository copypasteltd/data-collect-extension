# v0.5.0 — 可配置20倍限额

用户最新要求为20倍而不是早期讨论的200倍。单批默认及最大1280MiB=1.25GiB（约1.2GB）。这是本地交付，未自动公开新的GitHub Release。

- 侧栏新增可折叠限额设置，容量/队列/采样三组倍率1–20整数，默认20，支持保存和恢复；即时展示实际上限，异常不伪保存。
- 设置保存在扩展本地，重开可读；每个新批次固化启动时的设置，录制中修改只影响下一批。旧批次按原1倍读取，不重写预算。
- 采集、存储、后台接纳、导出和读取skill使用匹配限额，避免前端已提高仍被后端64MiB/2MiB旧常量拒绝。
- 长页面/输入按不超过1MiB的协议消息分片，有真实确认和Unicode边界保护，最终内容与事件同事务保存；不恢复旧全浏览器/全样式/数据库镜像通道。
- 增量SHA256/CRC、游标分页及OPFS磁盘输出替换全批数组和整包内存缓存；下载后清理本次输出，不清录制。STORE流式打包，压缩率可能比旧压缩ZIP低。
- 配套skill0.5.0核设置快照、实际事件字节/引用数/正文及预算；兼容旧v3和v1/v2。

验证：500项JS、58项Python回归通过；原生两批1/20设置和实际长Unicode前后值/3MiB ASCII页面/正文通过；130条分片最大327997B，无代理字符断开；320px无横向溢出。72MiB保存与磁盘ZIP导出实际成功，ZIP75511309B、约4.9秒（固定本机样本）。

独立审查发现并关闭分片字符规格不一致和读取器未落实每条事件限额两项问题。最大1.25GiB整批满载未实际压测，ZIP64高位仅做编码边界和小包实际读取，不冒称大于4GiB真实导出。

时间等待/权限/根业务范围保持原规则；磁盘不足、浏览器限制和通信/存储失败仍可提前结束。当前本机安装文件更新后需刷新原扩展，未代用户开启或开始录制。
