## 1. 更新目标与边界

### 1.1 目标

在现有开始、停止、批次选择和 ZIP 导出的基础上，完善用户实际经过的页面内容、视觉表现、操作、请求和浏览器数据的采集、关联和整理，使记录包可用于：

1. 查找每个已观察页面、页面实例、框架、操作、状态变化和对应截图。
2. 获取浏览器实际提供的原始数据、资源及其类型，并识别读取失败或不完整的部分。
3. 查找观察到的接口样本、字段、数据类型以及页面和操作的关联证据。
4. 在插件外依据证据重建已观察页面和流程，并区分直接观察、推断和缺失。

### 1.2 不得改变的产品约束

| 项目 | 约束 |
| --- | --- |
| 插件界面 | 所有插件交互在 Chrome 侧边栏内；只提供录制、停止、批次识别与选择、导出，以及必要的状态和错误提示。 |
| 内容展示 | 插件不展示页面、截图、接口、数据字典等采集内容；不增加插件内查看、导入、回放、分析或独立页面。 |
| 系统环境 | Windows 和 macOS 上用户只需符合版本要求的 Chrome 即可加载已解压插件；Node.js、Python 等仅用于开发或插件外工具，不是插件运行依赖。 |
| 数据原值 | 不对实际取得的数据进行自动脱敏、字段遮挡或静默替换。保留原始证据；派生整理结果单独保存，不覆盖原始证据。 |
| 本地处理 | 录制、整理与导出在本机完成，不主动上传；ZIP 是否加密按当前产品约定处理，不能将未加密归档描述为加密。 |
| 操作影响 | 采集不应主动提交表单、修改业务数据或刷新页面；长页面采集应优先使用不改变用户页面状态的方法，无法完成时记录原因。 |
| 开发环境 | 开发和验证不使用 Docker、WSL 或其他本地虚拟化环境；测试后关闭测试创建的浏览器和标签，不关闭用户原有浏览器。 |

### 1.3 完整性的可验收定义

“完整”以**录制期间、授权范围内、浏览器实际可观察且成功取得的内容**为目标，不把不能观察的内容声称为已采集。对于浏览器拒绝、页面未加载、调试连接不可用、系统资源不足、页面关闭、采集器失败或用户中止等情况，必须记录具体结果和影响范围。

未访问页面、未展开或未加载的数据、未触发接口和业务分支、浏览器没有提供的原始网络字节、服务端数据库及源码，不属于可由录制保证恢复的内容。即使缺口统计为零，也不证明不存在浏览器未报告或系统无法发现的缺口。

## 3. 统一数据与结果要求

### 3.1 原始证据和派生结果

| 层次 | 必须保存的内容 | 规则 |
| --- | --- | --- |
| 原始证据 | 浏览器实际返回的 DOM、样式、资源字节、操作、请求、响应和可读取的站点数据，以及其来源、时间和状态。 | 不脱敏、不覆盖；浏览器只返回解码文本时如实标识，不能声称取得原始 HTTP 字节。 |
| 标准化结果 | 对原始事件的解析、字段路径、数据类型、资源和页面关联、去重索引。 | 必须能回溯到原始事件、文件及位置；解析失败不丢弃原始内容。 |
| 推断结果 | 基于已观察样本的字段类型、页面关系、接口归类和可能的流程关联。 | 标记为推断，保留样本来源、冲突和未确认项；不把单次观察当作完整服务端契约。 |

“清洗”在本文中指解析、规范化、关联和可追溯整理，不指移除敏感值或修改原始数据。需要生成隔离的展示快照时，可另存处理后的派生副本，但不能以该副本替代原始证据。

### 3.2 记录身份与时间

- 每批次具有唯一 ID；每个标签、顶层页面实例、框架、文档、操作、请求、资源和截图具有可引用的标识。
- 页面刷新、导航、同 URL 重访及 SPA 状态变化应有明确区分；框架记录包含所属标签、父框架及文档身份，不能将旧文档资源套到新文档。
- 保存事件发生时间、采集开始和完成时间、批次内顺序及必要的视口信息；跨进程或跨页面的时间不应被当作严格因果顺序。
- 记录关联方式和可靠程度：直接关联、基于时序的候选关联、无法确认。不得把候选关系静默当成确定事实。

### 3.3 状态、限制与恢复

- 每项结果或资源应明确区分 `captured`、`partial`、`unavailable`、`not_observed`、`unknown`、`not_applicable` 等状态，并保留错误类型、原因、时间、来源及可知的原始大小或数量。最终字段名以实现时的格式规范为准。
- 不以占位字符串冒充原始值；当取得原值但无法整理时保留原值并标记整理失败。当浏览器根本没有提供数据时，记录不可用而不是虚构内容。
- 大数据采用分段、流式或增量落盘；任何配额、超时、容量或数量边界必须可发现、可归因，不能无提示丢弃。具体边界通过实际性能测试确定，不预先承诺无限容量。
- 明确已保存、未确认和失败范围；进程中断后保留已确认写入的数据。重试应幂等，不能重复事件、覆盖较新批次或将资源关联到错误页面。
- 停止与导出不得永久阻塞；错误、超时和恢复结果进入批次或记录包。侧边栏仅显示操作所需状态与错误，不展示采集内容。

## 9. 导出格式与兼容性

### 9.1 建议目录

以下是新格式的**设计目标示例**，具体文件名和格式版本在实现时固定，不能把示例目录当作 v0.1.6 已存在的内容。

```text
manifest.json                  # 格式版本、批次、环境、范围、状态、能力与缺口摘要
integrity.json                 # 文件路径、字节大小和 SHA-256
timeline/                      # 分段事件、检查点和关联引用
pages/                         # 原始 DOM、页面/框架元信息与派生快照
styles/                        # 原始样式、计算样式和主题整理结果
screenshots/                   # 视口、整页或分片截图与元数据
resources/                     # 原始图片、字体、文件及资源索引
network/                       # 请求、响应、正文分段及关联索引
browser-data/                  # Cookie、存储、IndexedDB、Cache 等快照
indexes/                       # 页面、操作、资源和接口关联清单
data-dictionary/               # 观察到的字段、类型、样本和证据引用
coverage/                      # 能力状态、缺口、失败原因及恢复记录
```

### 9.2 归档契约

1. 清单必须列出格式版本、生成器版本、批次状态、开始与结束时间、采集范围、事件分段、资源索引、能力及已知缺口；`ready` 不等于全部内容完整。
2. 每个附件包含可验证的大小和哈希；资源引用与文件路径可一一核对。完整性校验只能证明文件与清单一致，不证明记录来源或真实性。
3. 分段应支持大文件和中断恢复；采集完成与导出完成分别记录。打包失败不得删除本地批次或改写原始证据。
4. 规范化和数据字典必须引用原始事件及附件；路径、类型、编码、采集状态和实际值不得混用。
5. 新格式应版本化；保留 v1/v2 旧包的读取能力，并更新仓库内 `app/skills/extension-logic-clone` 与相应安装说明。旧包缺失字段标记为未知，不凭新格式要求补造。
6. 大记录需验证浏览器内存、磁盘、压缩和下载行为。若平台或资源限制阻止处理，报告实际失败及可恢复范围，不能静默导出不完整包。

## 11. 验证与交付标准

### 11.1 自动与浏览器测试

- 为 01–26 分别建立可重复的本地测试页面或数据样本，按对应验收要点比较原值、类型、文件哈希、关联和缺口，不只检查文件是否存在。
- 覆盖大于旧限制的 DOM、CSS、请求响应、本地存储和 IndexedDB 样本，以及大图片、字体、Canvas 和二进制文件；测试分段重组、重复数据、编码及资源索引。
- 覆盖单页路由、iframe、Shadow DOM、延迟加载、虚拟列表、滚动、动态表单、多标签及快速操作；对截图验证尺寸、像素、时序和关联。
- 注入跨域拒绝、不可读内容、磁盘满、事务失败、消息超时、浏览器后台重启、页面关闭及中断导出；核对错误和已保存数据，不把失败当作完整。
- 测试持续录制、队列积压和大包导出对内存与界面响应的影响；在目标环境确定可接受阈值并记录测试条件。
- 用真实 Chrome 扩展环境测试 Windows 和 macOS 的安装、录制、停止及导出；仅在实际完成对应系统真机测试后宣称该系统已验证。测试浏览器、标签及临时服务由测试自行关闭。

### 11.2 交付检查

1. 01–26 均有对应实现、测试和结果；不能实现或无法验证的项有具体原因、影响及替代证据，不宣称已完成。
2. 原始证据、派生结果和类型推断可分别读取与追溯；超过旧阈值的样本不再静默替换或整项丢弃。
3. ZIP 可在另一台只安装 Chrome 的录制端生成；接收端解析工具的运行环境及版本单独写明，不混同于插件运行要求。
4. 中断、配额不足或浏览器拒绝时，已保存内容可恢复或明确说明无法恢复，缺口可在包中定位。
5. 更新双语 README、安装说明、格式说明、技能、变更记录和测试结果；构建并核验实际发布附件。插件侧边栏不增加采集内容展示或独立页面。
