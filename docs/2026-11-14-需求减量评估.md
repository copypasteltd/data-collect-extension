# 逻辑记录：需求减量评估草案

状态：**用户已批准按本方案构建新release并更新原插件目录**。v0.4.0实际实现与验证以[实施合同](<精简/2026-11-14-v0.4.0/CONTRACT.md>)和[报告](<精简/2026-11-14-v0.4.0/REPORT.md>)为准；下文保留最初评估口径，候选预算/门槛不能替代实际证据。用户明确不考虑旧数据，旧批次迁移和救援不列本次工作，也不删除旧数据。

## 一、重新定义目标

从“尽力全量保存浏览器页面、视觉、网络及站点存储，并在导出时生成全部分析产物”收口为：

> 对用户指定的一个业务标签，记录实际完成的关键业务步骤、必要页面状态与请求响应样本；接收者据此理解并重建观察到的页面和流程。

不是全站源码恢复、精确自动回放、浏览器备份、全域接口契约或逐像素还原。保留开始、停止、选批次、导出四操作；不以新增Lite/Standard/Full多模式设置掩盖默认过重。

真实统计依据：已测主要压缩前导出内容16.507GB，其中自动主题及其它派生15.110GB（91.53%）；关闭自动派生仍有原始事件与附件1.398GB。移除派生只解决一层，必须同时收缩采集义务。各项收益重叠，不可简单相加或推算一定减至某个ZIP大小。

## 二、保留八项核心义务

| 核心义务 | 收口后的最低要求 | 明确不保证 |
| --- | --- | --- |
| 1. 范围明确 | 开始时绑定一个根业务标签；同标签导航（含跨域）持续跟踪；必要业务框架及可明确归因的一个流程子页共享总预算 | 自动全profile、无关窗口/标签、不可归因新页；跨域SSO/框架权限不足的内容不保证 |
| 2. 关键操作 | 点击、提交、字段稳定值与可知前值、选择/勾选、必要键盘语义、滚动终点；业务弹窗/下拉/校验失败也属步骤 | 全指针轨迹、每次hover/focus触发完整页面采集 |
| 3. 页面状态 | 一个规范DOM表示；初始基线+提交/导航/稳定关键状态检查点，必要变化有引用 | 同时保存原始DOM和展示DOM；每个Mutation都重抄整页 |
| 4. 视觉依赖 | 当前页面实际依赖的必要CSS和资源，内容去重一次；可知来源与缺口 | 全站字体/图像/脚本下载、全元素全属性全伪元素扫描 |
| 5. 关键截图 | 当前视口PNG、初始/关键步骤后；重复合并与真实时间关系可查 | 每个事件独立前后截图、默认整页分片、视频/Canvas另存完整像素 |
| 6. 业务接口样本 | 范围内fetch/XHR/文档必要请求的元数据及有预算正文，参数/结果原值不改写 | 所有二进制/下载/流帧/历史缓存与业务因果自动证明 |
| 7. 身份与限制 | 页面/步骤/请求/内容引用、时间/封存/hash、采集政策/未采原因 | 未观察视为不存在、达到预算却显示完整 |
| 8. 本地交付 | 只打包已保存数据与轻量manifest/关系/hash；控制可停止，失败可重试 | 导出时重建整套主题/字段图谱/接口规范 |

范围规则不靠“当前激活页”漂移：开始绑定根tabId，用户切到无关现有页不自动接管。根页同标签跨域导航继续；由已录业务操作打开、有opener且能确认归属的一个业务子页可随流程纳入（同一时刻至多根页+一个子页，共享预算），不是扫描所有新页。无opener/无法确认归属或超范围时只记未纳入原因。业务iframe按已授权可读范围进入同预算；跨源不可读只保父页截图/框架元信息和缺口，不说已获得内部DOM。若第一版明确只支持根标签，必须把依赖弹出页的流程排除，不能同时承诺覆盖该流程。

## 三、逐类删减

| 现有义务 | 默认版建议 | 失去什么/补偿 |
| --- | --- | --- |
| 全浏览器所有获准页 | 删除，根业务标签及明确归属的一个子页 | 不采后台页，无法归因新页明确缺口/分段 |
| 每秒/鼠标/变更触发全快照 | 删除，重要业务状态检查点+必要变化 | 不保证两检查点之间每个视觉瞬态 |
| 双份HTML（sourceHtml/html） | 只保规范结构证据，展示版本离线生成 | 默认包不含现成可执行展示副本 |
| 原始CSS反复按页复制 | 内容hash一次保存+使用引用 | 无损去重可保同内容，不把同URL当同字节 |
| 全元素computedStyle | 默认删除 | CSS继承最终结果不再全节点保存；DOM+CSS+截图支持重建而非绝对像素一致 |
| 全伪元素/继承自定义变量 | 默认删除逐节点逐属性记录；主题相关信息只在CSS一次保存 | 无逐节点解析后主题表，按需离线计算 |
| hover/focus目标及25后代样式 | 删除连续扫描；若改变业务状态用检查点+截图 | 纯装饰hover不保证独立还原 |
| 字体/图片/脚本全资源镜像 | 只必要视觉依赖，体积有预算，内容去重 | 不保证完全离线全站加载；核心图标/布局资源按重建需求保留 |
| 全页PNG及长页分片 | 默认删除，只当前视口；特殊长页另算以后需求 | 不在一次录制里证明整页所有位置 |
| Canvas另存像素及WebGL通道 | 默认删除，截图保所见；业务需图表数据可从API样本获取 | 无可编辑图表/原绘图程序，跨域等限制说明 |
| 全输入按键/指针流 | 字段稳定值、操作前值和必要语义事件；保弹窗/下拉/校验中间态 | 不保证逐键自动回放/原鼠标轨迹 |
| 所有HTTP正文及轮询 | 必要业务样本，重复内容引用/次数，保不同业务结果 | 不保等价心跳每次重复正文；去重按内容不能仅按URL |
| WebSocket/SSE所有帧 | 默认只连接/消息数量与大小元数据 | 实时聊天/交易/流式业务需独立样本方案，不能假称已覆盖 |
| Cookie全域快照/变更 | 默认不另采Cookie值；相关请求头是否保原值明确披露 | 不保证恢复登录态；不得偷偷脱敏已承诺保留的请求原文 |
| Storage全键每秒扫描 | 默认取消；仅业务确需时初末差异另立需求 | 无全站持久化状态备份 |
| IndexedDB全库扫描 | 删除 | 不恢复离线数据库；以实际页面/API证据重建观察流程 |
| Cache Storage全响应 | 删除 | 不备份缓存；不影响已记录的实际请求响应 |
| 上传文件/所有Blob原字节 | 默认元数据和请求样本，文件内容不另读 | 文件上传不可自动复演，测试复建需样本文件另提供 |
| 字段/主题/类型/接口规范 | 全移出主导出，按需离线生成 | 基础包不附现成分析报告，但原必要样本可回查 |

保留原值原则不变：**明确不采某通道**不等于读取后静默删改/脱敏；不同表述和schema必须一致。离线重建使用样本模拟，不向真实后台自动重发POST/PUT/DELETE。隐私/会话凭据的默认策略需要与新的范围合同同步，不能把“脱敏”和“减量”混为一谈。

## 四、三种减量手段必须分开

1. **需求删减（有能力代价）**：不采无关标签、全库、全缓存、全元素视觉普查。
2. **无损表示优化（不变承诺）**：同内容hash去重、引用表、一次定义上下文、批量编码；原相同字节可重建。
3. **有损策略（需告知）**：采样、截断、预算后不采、截图降分辨率等。首选少拍/去重而不是降PNG质量；任何有损必须有not_collected_by_policy/partial及大小/原因，不能伪称完整。

没有以上区分，只把同一套义务塞进Worker/gzip或加超时，并不系统性解决膨胀。

## 五、建议预算（待样本标定，不是当前能力或已批准需求）

| 层次 | 建议初值 | 行为 |
| --- | --- | --- |
| 单批已接纳的唯一逻辑内容+元数据 | 64MiB上限，48MiB预警 | 所有正文/DOM/CSS/附件共享，内容同hash按一次计；其中1MiB预留最终清单/停止/缺口记录，普通采集到63MiB受控停止 |
| 单个请求/响应正文 | 2MiB上限 | 可知超限时只留元数据和原因；未知大小读取需实际受控，不可先分配任意大buffer才判断 |
| 正文样本集合 | 24MiB子预算 | 正文去重并保留不同业务参数/结果，不按URL直接抹掉业务差异 |
| DOM检查点集合 | 16MiB子预算 | 一个表示；只关键状态，重复引用，达到预算标记不采 |
| 必要CSS/图片/字体等资源 | 8MiB子预算 | 只范围内必要依赖、按内容hash一次 |
| 视口PNG | 12MiB子预算、关键状态合并 | 优先减少重复拍摄而非改截图像素；不是每click独立前后图 |
| 事件/manifest/引用元数据 | 4MiB子预算 | pointer/scroll节流，metadata也不能无限增 |
| 主导出扩张 | 未压缩条目总量≤已保存唯一内容+轻量元数据（额外≤5%或1MiB取大） | 不额外生成主题/字典分析文件；ZIP压缩率不作硬保证 |

子预算合计64MiB，其中事件/元数据4MiB包含1MiB收尾预留；不是每一类都可以额外突破总预算。全部是采前/接纳前和整个队列共同核算，不是导出后才检查；达到上限是“按容量策略停止/部分结果”，不是通信故障。页内已经分配的巨型对象、未知Content-Length、CDP正文读取限界需实现实测，不承诺64MiB等于进程内存峰值。

建议容量后不自动删除、循环覆盖或继续无限采集。UI显示已记录量/容量停止原因，不新增内容浏览器或复杂设置页。用户期望更高档位时先另做负载与价值评估，不同时养多个未经验证录制模式。

## 六、重定验收，不沿用“全量样本越大越好”

以下为候选门槛，须在约定参考机与固定代表页面上校准：

- 单个业务标签60秒、10个关键操作、普通JSON API：最终ZIP以5–20MB为目标，≤20MB作为该样本待确认上限；不是任意站点保证。
- 同时打开其它20个标签：它们产生的网络、DOM、缓存不得进入批次；范围声明须与实际事件身份一致。
- 页面有5000个CSS变量、数千元素及伪元素：主包不能生成element×pseudo×variable的派生行；额外包体不因变量继承逐节点平方放大。
- 页面重复无业务变化20次：相同CSS/DOM/body内容只存一次，事件引用/计数保留。不同参数/不同结果不可误去重。
- 页面脚本不断更新计时器/动画：不得按每次Mutation产生完整HTML+样式；关键业务结果和截图仍能回查。
- 业务oracle：旧/新字段、提交成功、拒绝分支、余额/状态、请求响应与关键视觉证明可定位；采集本身不额外提交请求/业务写。
- 预算边界：超过一个2MiB正文或总64MiB时，原已确认内容可导出，显式policy原因/实际大小，停止保持可用，无静默丢弃、假captured或无限等待；必要正文被策略排除的场景只能判“包可用/采集部分”，不能说该分支复刻已通过。
- 参考样本重复至少20轮，P95停止≤5秒、导出≤10秒是候选目标；浏览器挂起/真实异常另报，不用删断言或扩大目标制造通过。
- 导出后直接校验manifest/原文件hash/批次身份和字节量；不先展开其它派生数据库才能认定包可用。
- 实际复建验收：让未接触原站的接收者只凭包，在样本服务上实现关键页面、弹窗/下拉、校验失败、成功/拒绝分支；核对结构、文案、主要布局/颜色、输入和结果。不能用ZIP校验成功代替页面与业务重建成功。

不再以“全库大对象、18MB正文、整页6分片、逐元素全部样式”均默认开启作为基础版通过条件。若未来专项需要，属于独立诊断任务，不重新塞回默认义务。

## 七、实施顺序（本轮不执行）

1. **先冻结新范围合同**：单标签、八义务、删除/不保证项、policy状态/预算/样本门槛一次确认。旧数据不迁移、不救援、不兼容重导出。
2. **断开主要生产源**：全browser→tab；关闭computed/pseudo/hover扫描、全库/缓存、自动全资源与全页；原值主事件路径保留。
3. **简化状态证据与内容引用**：单DOM表示、关键检查点、必要CSS/图像去重、API不同业务样本识别，避免引入复杂通用回放引擎。
4. **主导出改为已落盘交付**：不跑主题/字典解析；总预算、限流、hash/计数前置可追溯。
5. **用上述业务与容量场景真实验证后再交付**：版本/新格式范围明确，私有真实记录不提交。

## 八、损失与保留

明确失去：全浏览器活动、全站离线数据库、完整静态资源镜像、所有CSS最终值和伪元素逐节点证据、全页逐像素/逐键回放、原始上传文件自动重放，以及现成自动主题/字段分析报告。

保留：实际目标页面的业务路径、输入前后和结果、关键页面结构、必要视觉依赖及PNG、已观察业务请求响应、可知关联/不确定性、完整性和限额状态。页面重建可在这些证据基础上实现，但不保证完整源码、绝对像素或未走过分支。

最终建议：**一个轻量默认版，八项核心义务，重分析从主采集/导出合同移出；不以复杂配置把责任推回用户。**
