# 浏览器操作与业务逻辑记录系统：技术开发文档

版本：1.1<br>
日期：2026-11-09<br>
状态：技术设计草案，待目标站点验证<br>
需求依据：[Chrome 扩展需求梳理](./Chrome扩展需求梳理.md)<br>
适用范围：用户实际访问的页面及实际触发的流程。

本文件描述目标架构和开发方案，不能视为其中所有条目已完成。当前代码和可用范围请参考 [插件安装与使用说明](./插件安装与使用说明.md)；实际实现与本设计之间仍存在差异，例如当前以完整页面快照为主，尚未实现文中规划的 DOM 增量重放。

## 1. 技术目标与交付边界

构建 Chrome 扩展，实现操作和页面采集、网络及状态采集、本地归档、ZIP 下载、跨环境导入、只读回放和重建资料整理。所有用户界面均为扩展侧边栏内的子页面，不打开独立网页或浏览器标签页。记录应尽量保留页面和业务流程的可追溯证据，对无法获取、被脱敏和被截断的数据明确标记。

本方案将页面、事件、网络等观察数据与由其推导出的业务说明分开保存。未走过的页面与分支、服务端内部实现不作为本方案的既定覆盖目标。对已走过的流程也不能保证所有数据均能获得，验收应以实际采集结果和缺口报告为依据。

**产品决策状态**：本文给出便于工程启动的默认方案，范围选择、保留期限、允许采集的数据、回放深度、目标 Chrome 版本及部署方式尚待确认；默认方案不是已经批准的产品要求。设计中的容量、时间及性能示例均须通过目标环境测试后确定。

## 2. 系统组成

```text
Chrome 扩展
  侧边栏 UI ── 控制消息 ── Service Worker / 录制协调器
                               ├─ 权限和范围管理
                               ├─ 标签、页面和导航管理
                               ├─ 网络与调试目标管理 (chrome.debugger / CDP)
                               ├─ 截图调度及结果关联
                               ├─ 状态机、事件汇聚、持久化
                               └─ 归档与下载协调
  页面 Content Script ────────┤
    操作、页面结构、状态变化    │
  已授权的页面/帧 ────────────┘
  扩展本地 IndexedDB / Blob ── 归档器 ── ZIP

侧边栏内的查看子页面
  ZIP 导入与校验 → 索引 → 时间线 / 页面快照 / 截图 / 网络 / 流程
                             └─ 已观察页面、流程和接口资料导出
```

### 2.1 建议技术选型

| 部分 | 建议 | 选择依据与待验证点 |
| --- | --- | --- |
| 扩展平台 | Chrome Manifest V3，当前实现使用 JavaScript | 侧边栏与扩展 API；当前构建声明 Chrome 125+，实际兼容范围仍需测试 |
| 面板 | React 或现有团队熟悉的轻量 UI 框架 | 仅负责交互，不承担录制状态的唯一副本 |
| 页面采集 | content script + DOM 事件 / MutationObserver | 每个可注入帧单独运行；框架与站点需实测 |
| 网络 | `chrome.debugger` 与 CDP Network；按需使用 `webRequest` 补充 | 验证多目标、响应体、WebSocket 和调试连接冲突 |
| 本地持久化 | IndexedDB 存结构化数据、Blob 与检查点；小型设置可放扩展 storage | 支持事务和增量落盘，容量与导出性能需实测 |
| ZIP | 支持流式读写及校验的成熟库 | 不在内存中拼装整个大包；选型时验证浏览器、许可证及安全性 |
| 查看器 | 扩展侧边栏子页面，复用记录格式 | 必须可在侧边栏内操作；需可离线运行和隔离不可信内容 |
| 构建与测试 | TypeScript、Vite、单元测试及 Playwright 自动化 | 使用真实 Chrome 扩展环境补充浏览器测试 |

不引入 Docker 或 WSL。开发、测试及工具链使用本机原生环境。需用户许可的资源、站点和业务系统应在明确授权范围内使用。

### 2.2 关键设计原则

1. 先记录观察事实，再生成关联与推断；每项推断保留证据及置信状态。
2. 采集前明确范围和授权，敏感数据在持久化之前按策略处理；不隐式上传。
3. 每个采集器记录自身健康状态和缺口，失败不能被吞掉。
4. 原始记录顺序和关联可复查；跨来源时间不能默认为严格因果顺序。
5. 不依赖 service worker 常驻或全局变量；每个环节可中断、恢复或输出部分结果。
6. 回放默认隔离且只读；不执行导入包中的站点脚本，不携带真实凭据访问站点。

## 3. 权限和运行环境

| 能力 | 候选权限 / API | 用途与约束 |
| --- | --- | --- |
| 侧边栏 | `sidePanel` | 展示控制界面；配合 action 打开 |
| 注入脚本 | `scripting`、目标站点 host permissions | 在授权页面及可访问帧注入采集器；`activeTab` 是临时授权，不能替代所有长期多站点场景 |
| 浏览器信息 | `tabs`、`webNavigation`，按需申请 | 标签及导航变化，敏感字段依权限而定 |
| 网络与截图 | `debugger` / CDP；`tabs.captureVisibleTab` | 每个调试目标需要管理生命周期；截图只针对指定窗口当前活动标签可见区域 |
| Cookie | `cookies` 和对应 host permissions | 查询指定 store / 分区中可访问的 Cookie；范围和具体分区 API 支持需按目标 Chrome 版本验证 |
| 设置与下载 | `storage`、`downloads` | 配置及下载管理；具体存储选择按数据量决定 |

`webRequest` 可作元数据补充，但不应把它当作完整响应体或 WebSocket 消息来源。权限按实际功能申请，站点授权优先按需申请；缺权限时列出受影响能力。无痕模式依赖用户在 Chrome 中单独允许，默认方案不启用。

**截图约束**：`captureVisibleTab` 官方限制每秒最多 2 次，并受活动标签和权限约束；调度器必须实现全局速率限制、合并和结果标记，不能承诺每个事件独立截图。扩展无法注入的页面、浏览器 UI、原生对话框、受保护内容等均需逐项记录实际能力，不假定截图和脚本注入具有相同覆盖范围。

## 5. 状态机与生命周期

### 5.1 状态和转移

```text
idle → preparing → recording ↔ paused → stopping → finalizing → ready
          │            │          │           │
          └────────────┴──────────┴───────────┴─→ interrupted / failed
```

- `preparing`：持久化任务配置和授权结果，检查范围、存储、采集器及调试目标；逐项记录初始化结果。
- `recording`：开启采集、事件落盘和健康状态监测。开始边界为采集器准备结果写入的时间，未就绪采集器产生明确缺口。
- `paused`：停止接收业务数据并记录区间；恢复时重新检查权限/目标，建立新的页面基线。是否交付暂停功能待定。
- `stopping`：标记截止时间，停止接收新操作；对已接收数据及在途请求进行有界收尾，截止和超时规则写入记录。
- `finalizing`：写入检查点、统计、清单，打包并校验；可重试且不能重复计数。
- `ready`：归档成功，可下载；结果可为 `complete_with_gaps`，不得将缺口隐藏。
- `interrupted`：浏览器或扩展异常中断，保留最后已确认写入的数据，记录最后已知时间，重启后提示恢复或导出部分结果。
- `failed`：初始化或归档无法继续；保存原因及已完成部分，不自动删除。

### 5.2 幂等及恢复

使用 `sessionId + operationId` 标识开始、停止、归档等命令；重复提交返回已有执行结果。任务状态迁移和必要元数据在 IndexedDB 事务内提交。每个采集器定期确认已持久化序号；重启时以持久状态恢复，不假定内存缓冲仍存在。发生强制终止时，无法确认丢失的事件数量，应标记“未知缺口”而非计算为零。

## 6. 采集范围与页面生命周期

### 6.1 范围规则

配置包含起始窗口、初始标签、允许的 URL 模式、新标签跟踪规则、跨域跳转行为、第三方帧处理及无痕配置。建议初始原型只覆盖用户选择并授权的标签和域，其他范围按选择逐步扩展；这只是默认工程方案，最终以产品决定为准。

开始时页面可能早已加载：记录当前状态与 `captureStartedAfterLoad: true`，不声称捕获启动前请求。需要观察完整加载时由用户主动刷新或重新进入，系统不得未经许可自动刷新。

### 6.2 页面与帧标识

- `windowId`、`tabId` 为浏览器运行时标识，不应作为跨会话的永久唯一标识。
- `pageId` 对应一次顶层文档或约定的导航实例；重载产生新实例。SPA 的 `history` / hash 跳转产生路由事件和新状态，是否拆分页面实例在索引中统一规定。
- `frameKey` 由任务内稳定 ID 标识，另外保存 Chrome frame/document、CDP target/session 的映射；跨进程 iframe、导航和关闭时更新映射。
- 记录页面实例的起止时间、父子帧、URL 变化及是否进入权限范围；未知映射显式标注。

### 6.3 注入时机

优先使用授权范围内的早期注入以减少页面加载期缺口；对用户在已打开页面开始录制的场景主动尝试注入并创建初始快照。导航、帧创建和权限变化后重新评估。注入失败、受限制页面、子帧权限不足和目标创建前的活动均写入覆盖报告。

## 7. 统一数据契约

### 7.1 通用事件结构

```json
{
  "schemaVersion": "1.0.0",
  "sessionId": "s_01",
  "segmentId": "seg_01",
  "eventId": "ev_01",
  "producerId": "content-frame-01",
  "producerSeq": 42,
  "ingestSeq": 87,
  "kind": "interaction.click",
  "time": { "wallTimeMs": 1794211200000, "monotonicMs": 1245.2, "clockDomain": "frame_01" },
  "context": { "windowKey": "w_01", "tabKey": "t_01", "pageId": "p_01", "frameKey": "f_01" },
  "capture": { "status": "captured", "reason": null, "policyVersion": "policy_01" },
  "links": [{ "type": "observed_on", "targetId": "state_01", "confidence": "observed" }],
  "payload": {}
}
```

`producerSeq` 在同一采集器中递增；`ingestSeq` 是协调器接收顺序，不等于实际发生顺序。不同帧、CDP 和 worker 的单调时钟不能直接比较，需保存各自时钟域和标定样本，保留误差；校准不足时按可用墙钟与采集顺序展示，并标记不确定。示例时间仅演示结构。

### 7.2 统一采集状态

`captured`、`redacted`、`omitted_by_policy`、`truncated`、`unavailable`、`failed`、`not_applicable`；每项附原因、原始大小（可获取时）与采集器信息。截图附加 `shared` 或 `skipped` 等结果。状态按字段分别记录，不能以请求元数据成功代替响应体成功。

### 7.3 关联语义

| 关联 | 含义 |
| --- | --- |
| `observed_on` | 直接观察到事件发生于某页面/帧/状态 |
| `initiated_by` | 可由浏览器提供的 initiator 等证据直接支持的来源 |
| `temporal_candidate` | 因时间和上下文接近而候选关联，不代表因果 |
| `derived_from` | 流程、页面清单或接口草稿引用的来源 |
| `before` / `after` | 基于已知顺序的前后状态，注明截取时间 |

对象 ID 在任务内稳定，归档后不改变。任何重建或接口草稿应引用事件和请求 ID，保留采集策略和缺失状态。

## 8. 组件消息与数据管道

### 8.1 消息协议

```ts
type Message<T> = {
  version: 1;
  messageId: string;
  sessionId: string;
  source: string;
  sentAtMs: number;
  kind: string;
  payload: T;
};
type Ack = { messageId: string; status: 'persisted' | 'rejected'; reason?: string };
```

消息类型包括 `session.start/stop`、`collector.ready/error`、`events.batch`、`snapshot.chunk`、`screenshot.request/result`、`network.update`、`storage.change`、`archive.progress/result`。接收者按 `messageId` 去重；只有完成事务后才回复 `persisted`。消息重复、端口断开和部分批次失败必须可处理。大 Blob 不放入普通消息假定可靠传输；采用分块并设大小上限，具体通道通过原型验证。

### 8.2 管道及背压

`采集 → 范围检查 → 结构化 → 敏感处理 → 有界队列 → 批量事务写入 → 确认 → 索引/统计`。高频事件可按预设规则合并；关键操作、导航和失败不得无声丢弃。队列达到上限时记录丢弃类别与时间、提示用户，必要时暂停或终止录制；不能为了跟上吞吐而无限占用内存。

### 8.3 数据一致性

批次写入保证事件、关联引用和该批次检查点同事务提交；大资源先分块落盘，再以已完成标记引用。归档只读取冻结后的持久化视图；停止时等待已确认批次及有界收尾，超时项列入缺口。跨采集器的最终排序使用时间和时钟域信息生成派生索引，不覆盖原始顺序。

## 9. 用户操作采集设计

内容脚本在支持的帧内以捕获阶段监听 `pointer`、`click`、键盘、`input`、`change`、`submit`、`focus`、`scroll`、`composition` 等事件，按事件类别规范化。SPA 路由需结合 Chrome 导航事件与经验证的历史 API 变化检测；主世界桥接如需使用，应最小化权限并验证来源，不信任页面自行发送的伪造消息。

元素定位保存优先级：稳定业务属性（经允许）→ 可访问角色和名称 → 标签及相对路径 → DOM 路径 → 坐标与边界框；避免只依赖动态 class。还需保存字段类型、操作前后可观察值、滚动容器和视口。区分用户真实事件与脚本生成事件，但不能仅凭 `isTrusted` 判断所有业务含义。

输入、剪贴板和选择项需在本地先按策略处理；默认不采集密码、验证码和身份认证凭据。文件选择默认不采集文件内容或本地完整路径；名称及元数据的处理由策略配置。用户输入法组合按事件序列处理，避免既记录中间内容又重复计入最终值。

## 10. 页面快照、变化与资源

### 10.1 快照和增量

建立页面/帧初始快照，记录文档结构、节点 ID、文本、属性、样式引用、输入状态、滚动及视口；`MutationObserver` 捕获节点增删、属性和文本变化，按原节点 ID 排序记录。动态表单值、滚动和样式表变化可能不由 DOM mutation 完整体现，须独立捕获或在检查点补全。

定期或在关键导航、显著状态变化后生成检查点；每个增量引用最近可用检查点和上一个增量序号。页面重载、采集器重启或节点映射失效时创建新基线；出现序号缺失时回放器提示断点，不继续假装连续。

快照中的脚本、事件处理属性、危险 URL、嵌入内容等不得在查看器中直接执行；建议构造受限的惰性展示模型。Shadow DOM、跨域帧、Canvas、WebGL、视频等应分别通过可获得结构、截图或占位说明处理，闭合 Shadow DOM 不应假定可读取。

### 10.2 资源

基于实际请求和页面引用建立资源清单，记录 URL、类型、内容哈希、大小、请求 ID 和采集结果。按 MIME 类型、单项大小及任务总额度决定保留；相同内容按哈希去重。资源读取可能因缓存、缓冲被回收或其他原因失败；保留元数据与失败原因，不使用额外请求悄然重新下载。

## 11. 网络采集设计

### 11.1 目标管理

对每个符合范围的标签执行调试附加并启用所需 CDP 域；维护 `tab → target/session → frame/page` 映射，处理目标创建、导航、关闭和断开。跨进程 iframe / worker 的子目标自动附加策略及可观察覆盖须在目标 Chrome 测试；附加失败或与其他调试器冲突时报告具体影响，不宣称全量覆盖。

### 11.2 请求生命周期

订阅请求发起、额外头信息、响应、加载结束或失败、重定向、缓存及 WebSocket 事件；以目标/会话、请求 ID 和重定向序号联合区分记录。事件可能乱序或缺失，允许先写部分记录后补全，并保存每一段状态。

加载完成后按策略尝试读取响应体；异步请求和页面关闭可能使主体无法取得。请求体、头、响应体分别执行大小限制和敏感处理，记录主体编码、是否截断和错误原因。流式、Service Worker、缓存、下载、二进制及 WebSocket 的覆盖须逐项验证。避免为获取主体改变或阻塞用户真实请求；拦截式增强需要单独设计及同意。

### 11.3 接口样本

依据实际方法、路径、查询与内容类型生成接口候选，保留每次请求/响应样本和操作关联。动态路径参数、字段类型、必填性只作推测；响应字段缺失不意味着字段永不存在。

## 12. 截图调度与隐私

关键事件进入截图请求队列；限制全局速率，按窗口/活动标签合并短时间请求，记录关联事件列表及实际捕获时间。捕获前后核对窗口活动标签与页面实例；若标签已切换，不将图像错误关联给原页面。捕获 API 异步，核对仍无法消除所有竞争，存在歧义时标注不确定。

原始截图只在内存中处理；根据用户策略遮挡已识别的敏感区域后才允许持久化。跨域帧或图片/Canvas 内的敏感信息不保证自动识别，应支持用户指定遮挡区域及关闭截图；无法按策略可靠遮挡时跳过截图并记录原因。导出的图片和索引均引用处理后资源。

截图不是精确的原子操作快照。可设置“事件后等待渲染”及最大等待时间；若等待超时、页面持续变化或被限流，记录不稳定或合并结果。滚动拼接整页会改变站点状态，作为独立可选功能而非默认行为。

## 13. Cookie 与站点存储

`chrome.cookies` 按授权域、store 和可用的分区能力获取初始快照及变化；需正确维护名称、域、路径、store 和分区等键，不跨无痕与普通会话混用。默认技术方案只保存经过策略处理的值，原始认证 Cookie 值和令牌不写入归档。

localStorage / sessionStorage 在相应源及帧的可访问上下文中采集；同一页面内的本地变更、跨页面事件和其他脚本写入的观察方式不同，需原型验证。IndexedDB、Cache Storage 和 Service Worker 的初始快照或变化取决于可用 API、源和分区、数据类型及大小；不能假定能原子读取全部内容。所有存储采集受站点授权、策略和容量上限约束。

## 14. 隐私与安全设计

### 14.1 数据处理策略

定义版本化策略：域名规则、字段名规则、元素选择器、内容类型、数据大小、截图区域及允许的业务字段。处理动作包括保留、遮罩、删除、摘要、截断和拒绝采集；同一策略覆盖 URL、输入、DOM、网络、日志、状态及导出。敏感检测有漏报风险，应支持人工排除和审查。

建议默认不持久化密码、验证码、Authorization、认证令牌和可用于接管账户的 Cookie 值；用户允许记录其他明文业务数据时，单独明确采集与分享风险。业务资料必须尽量保留以支持重建，脱敏造成的缺口应随记录报告，而不是让内容悄然消失。

### 14.2 信任边界

- 目标页面是非可信输入：校验消息来源、结构、大小和会话；主世界桥接不能作为可信授权或命令通道。
- 记录包是非可信输入：限制文件数量、展开大小和压缩比，拒绝绝对路径、`..`、重复冲突路径及超限文件；不依赖文件扩展名判断内容安全。
- 查看器默认不执行原站 JavaScript、不启用表单提交、不加载远程资源；在隔离上下文展示经过净化的内容，并实施 CSP。离线模拟严格匹配记录样本，未命中时显示未记录。
- 本地 IndexedDB 与普通 ZIP 不自动加密；如需密码加密，须另行选择成熟方案并定义密钥及恢复策略。日志不得包含明文凭据或原始敏感主体。

如需 Chrome Web Store 分发，需在发布前复核当时的权限、隐私披露与用户数据政策；本地存储不等于免除所有要求。

## 15. 持久化结构与容量

建议 IndexedDB 对象存储：`sessions`、`segments`、`pages`、`events`、`requests`、`snapshots`、`resources`、`blobs`、`collectorHealth`、`archiveJobs`；按 session、page、时间及类型建立必要索引。Blob 使用内容哈希引用与引用计数；大资源分块并记录完成状态。对象结构需有迁移版本，升级失败保留旧数据并报告。

写入批次与检查点同事务提交；空间使用与配额通过可用浏览器 API 估算，但估算值不等于可用磁盘保证。达到配置阈值时先预警，再限制高体积采集或暂停/停止，所有降级写入报告。清理任务仅删除用户选择且不再引用的数据；卸载扩展可能清除扩展本地存储，应提示用户及时导出。

## 16. 归档格式与完整性

ZIP 目录遵循需求文档中的 `manifest.json`、`timeline/`、`pages/`、`screenshots/`、`network/`、`state/`、`resources/`、`flows/`、`reports/` 和 `integrity.json`。文本采用 UTF-8；大规模事件建议 JSONL，二进制按哈希存放，路径与 MIME 类型由清单声明。

`manifest.json` 至少包括：格式版本、生成器版本、任务 ID、录制开始/停止时间、片段、环境、范围、采集配置、脱敏策略版本、任务状态、缺失摘要、索引与文件计数。不得嵌入凭据。

`integrity.json` 对包内其他文件列出规范化相对路径、字节数及 SHA-256；不对自身做递归哈希，ZIP 文件自身可在导出时单独计算。哈希仅用于检测损坏或意外变化，不提供身份认证。写入临时归档、完成校验后才标记可下载；部分包在清单中标记并保留缺口。

版本规则：主版本不兼容时拒绝或提示升级；次版本允许新增可忽略字段；查看器保留未知字段，不默默修改原始数据。具体兼容矩阵随版本发布维护。

## 17. 查看、回放与重建

### 17.1 导入与索引

流式检查清单、文件大小及哈希，通过后建立本地只读索引；数据量大时分块解析 JSONL。损坏、缺项、版本不兼容和策略脱敏分别报告。提供页面树、事件时间线、截图、网络、状态和流程视图，所有视图可通过 ID 跳转。

### 17.2 回放算法

按目标事件找到最近的有效检查点，在隔离展示层加载已净化快照，按序应用后续变化；同时叠加用户操作标记、截图和网络事件。若增量缺失、节点引用不存在或资源不可用，停在可确认状态或显示缺失占位，允许用户查看原始截图。

回放默认展示已记录轨迹而非执行原站代码。交互模拟可在后续实现：从用户动作匹配已录状态与请求样本，仅返回已录响应并禁止外网；匹配不唯一或未命中时提示，不能合成未观察结果。对真实站点自动重跑属于独立能力，须另行设计授权、风险控制和确认。

### 17.3 重建输出

生成页面与路由清单、模块候选、操作流程、接口样本及可选 OpenAPI 草稿。每条资料携带 `sourceIds`、观察次数、推断标识及缺失原因；不以静态样本声称恢复服务端实现。输出格式与可运行站点生成范围由产品决策。

## 18. 日志、诊断和覆盖报告

记录采集器初始化、心跳/连接变化、写入失败、截图合并、请求体不可用、脱敏和配额事件；日志只含必要元数据及错误码，不记录原始敏感值。覆盖报告以采集器观测到的对象为分母，分别统计事件已接收/已落盘、关键事件截图成功/共用/失败、请求元数据/主体结果以及页面/帧注入结果。

未进入权限范围、浏览器未暴露、录制前发生的行为不能被计算成已成功覆盖。报告同时展示未知范围及中断区间，不以单一百分比声称整个网站完整。

## 19. 测试与验收策略

| 层级 | 覆盖内容 | 通过条件 |
| --- | --- | --- |
| 单元测试 | 事件规范化、策略、队列、状态迁移、关联、路径校验、格式版本 | 边界与异常结果符合契约；禁止字段不进入持久化对象 |
| 集成测试 | IndexedDB 事务、重复消息、批量写入、归档/导入、哈希校验 | 部分写入与重试可恢复，文件和索引一致 |
| 浏览器测试 | 真实扩展加载、侧边栏、导航、SPA、截图和调试目标 | 约定测试环境中流程可完成，缺口与状态可见 |
| 网络测试 | 请求、重定向、错误、缓存、WebSocket、截断与主体不可取 | 分别验证元数据和主体，错误不造成误报成功 |
| 恢复测试 | worker 重启、浏览器异常退出、目标关闭、调试断开、空间不足 | 已确认数据保留；未知缺口、部分包和恢复路径正确 |
| 安全测试 | 脱敏泄漏、恶意 ZIP、路径穿越、压缩炸弹、脚本与外网访问 | 禁止内容不落盘/导出，导入不执行原站代码或提交操作 |
| 端到端 | 查询 → 详情 → 修改 → 提交 → 归档 → 另一环境导入 | 可通过证据追踪每个步骤、页面状态和相关请求 |

测试站点应包含跨域 iframe、动态 DOM、文件选择、Canvas、长列表和持续请求等场景。对每项不支持或受限行为也要验证报告是否准确；浏览器行为测试使用本机原生 Chrome，不调用 Docker 或 WSL。

## 20. 开发阶段与完成条件

### P0：可行性验证

建立最小扩展，验证侧边栏、指定站点注入、动作事件、截图限流、CDP 附加与请求/响应、帧覆盖和 IndexedDB 大对象。产出真实能力矩阵、失败样本、资源开销及建议基线；确定是否进入正式开发。

### P1：核心录制和归档

实现范围和授权、任务状态机、事件及页面基线、截图队列、网络采集、必要站点状态、脱敏、增量落盘、故障报告、ZIP 和下载。完成核心录制流程和恢复测试。

### P2：查看与只读回放

实现导入校验、页面与事件索引、截图/请求详情、检查点与增量回放、缺失展示。通过跨环境和恶意包测试。

### P3：重建资料

实现页面清单、实际流程整理、接口样本与规范草稿，提供证据追踪和人工修订能力。对实际测试流程验证资料与证据一致。

### P4：增强能力

根据 P0 数据决定复杂画面采集、实时通信增强、离线交互模拟与大包性能优化。真实站点自动重跑、自动生成可运行站点另立设计和验收。

## 21. 关键技术风险与待确认决策

| 事项 | 风险 / 影响 | 处理方式 |
| --- | --- | --- |
| 目标站点范围 | 不同站点的 iframe、缓存和反自动化影响采集 | 尽早选取代表站点进行 P0 验证 |
| 调试连接 | 附加失败或中断导致网络缺口 | 实时报告、记录中断区间、保留其他采集结果 |
| 图形与媒体 | DOM 无法表达所有视觉内容 | 截图兜底并标记不能结构化还原的内容 |
| 截图与脱敏 | 限流和隐藏敏感信息均影响完整度 | 显示处理结果，允许用户配置但不能隐瞒缺口 |
| 数据规模 | 长时间录制、资源和截图导致体积增长 | 增量写入、配额、去重及流式归档，阈值实测 |
| 恢复语义 | 强退可能丢失尚未确认数据 | 持久化确认、检查点和未知缺口标记 |
| 查看器交付 | 侧边栏狭窄空间影响时间线和详情展示 | 在侧边栏内实现分视图导航、响应式布局及离线读取 |
| 敏感数据政策 | 明文采集与分享可能泄露会话或业务信息 | 明确授权、字段规则、脱敏、保留和分发政策 |
| 质量目标 | 尚无明确设备、时长和可接受精度 | 选定目标站点和设备后制定量化指标与验收集 |
